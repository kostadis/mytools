# Cleric Builder 2024 - Implementation Plan

> **Note**: This document was created during the initial implementation. For future class builders, use the generalized template at `CLASS-BUILDER-TEMPLATE.md`.

## Overview
Create a Cleric character builder for D&D 2024 rules, mirroring the architecture and design of the existing Rogue Builder but adapted for Cleric-specific mechanics. The builder follows the same static site generator pattern: `data/cleric-2024.json` → `rpgbot.db` → `dist/cleric-2024-builder.html`.

## Implementation Status: ✅ COMPLETE

The cleric builder has been successfully implemented using the shared `builder.html` template. Key changes made to `builder.html` to support Cleric-specific features:

### Changes to builder.html
1. **Header**: Changed icon from ⚔ to ☀ for Cleric theme
2. **Tabs**: Changed "Subclass" tab to "Domain" (data-tab="subclass" kept for backward compatibility)
3. **Pane**: Changed pane title from "Subclass" to "Divine Domain"
4. **Skills**: Removed Expertise counters (e1-citem, e2-citem) - Clerics don't get Expertise
5. **Status Bar**: Changed `sb-sc` to `sb-dm` for Domain display
6. **Feats**: Removed Dragonmark Feats category (Clerics don't have Dragonmark Feats)
7. **Dynamic UI**: Uses `D.ui` config object for all class-specific text

### Data File Changes (data/cleric-2024.json)
1. Fixed `subclasses` array to use `"name"` instead of `"n"` (template requirement)
2. Updated `featDesc` to reflect 5 ASI slots (Clerics, not Rogues)
3. All other Cleric-specific data already correctly configured:
   - `skillPicks: 2` (Clerics pick 2 skills)
   - `hasExpertise: false` (no Expertise for Clerics)
   - `asiLevels: [4, 8, 12, 16, 19]` (5 slots)
   - Domain descriptions and options

## Core Design Principles
- **Consistency**: Maintain identical UI/UX patterns, CSS classes, and color scheme as the Rogue Builder
- **Accuracy**: Fully implement 2024 D&D rules: Wisdom from Background, Weapon Mastery system, three feat tiers (Origin/General/Epic Boons)
- **Simplicity**: Remove complexity that doesn't apply to Clerics (no Expertise, different ASI progression)
- **Clarity**: Emphasize Wisdom as primary stat and Divine Domain as core feature

## Key Differences from Rogue Builder

| Feature | Rogue | Cleric |
|--------|-------|--------|
| **Class Type** | Subclass (chosen at level 3) | Divine Domain (chosen at level 1) |
| **Primary Stat** | Dexterity | Wisdom |
| **Skill Picks** | 4 + Expertise tiers (L1/L6) | 2 (no Expertise) |
| **ASI Slots** | 6 (levels 4, 8, 10, 12, 16, 19) | 5 (levels 4, 8, 12, 16, 19) |
| **Weapon Mastery** | 2 slots | 2 slots |
| **Armor Proficiency** | Light only | Light, Medium, Heavy, Shields |
| **Core Features** | Sneak Attack, Reliable Talent, Cunning Strike | Channel Divinity, Turn Undead, Divine Domain features |
| **Feats** | Origin, General, Dragonmark | Origin, General (no Dragonmark) |
| **Epic Boons** | 1 at level 19 | 1 at level 19 |

## Build Process
```bash
# Seed the database with Cleric data
python3 seed.py cleric-2024

# Build the Cleric builder HTML
python3 build.py cleric-2024

# Output: dist/cleric-2024-builder.html (60KB)
```

## Architecture Notes
- The shared `builder.html` template uses `D.ui` config object to adapt to class-specific settings
- `D.ui.skillPicks` - defaults to 4 (overridden to 2 for Cleric)
- `D.ui.hasExpertise` - defaults to false (Cleric doesn't get Expertise)
- Status bar uses `sb-dm` instead of `sb-sc` for Domain display
- The template automatically hides Expertise counters when `hasExpertise` is false

## Notes

This implementation follows the "render within structure" principle: the structure (HTML layout, CSS classes, data format) is human-designed and verified, and the LLM is only responsible for rendering the content within that structure. This prevents precision errors in scope decisions while leveraging the LLM's strength in content generation.
