When a campaign has a large triage backlog — hundreds–thousands of UNKNOWN surface forms from `registry.py triage-candidates` — resolve them with a fan-out **Workflow** rather than inline. Each name is looked up in the **5etools MCP** and checked against `docs/entity_registry.yaml`; the output is a **DRAFT review CSV** (`surface, count, n_sources, resolution, suggested_name, fivetools_verdict, registry_status, why`). The human rules on every row — nothing is auto-written to the registry.

**Why:** It turns a noisy ~1500-row backlog into an actionable ~230-row CSV in one pass, keeps the LLM a *drafter* (the safe pipeline pattern — LLM proposes, human decides), offloads deterministic matching to code so agents only judge, and the canary + batching make it cheap and reliable. Validated on OOTA (2026-07-14, 238 candidates, 20 agents, 0 failures) and the user asked to keep the loop.

**The tokenizer is a high-recall gap-finder, not a classifier.** `proper_noun_counts` deliberately over-nominates: it surfaces every proper-noun-shaped token the registry doesn't know, which is a *mix* of genuine missed entities (the valuable catch) and noise it can't tell apart (common words, generics, artifacts). A missed real entity is the expensive failure; a spurious `blink` is cheap and the resolution stage cleans it up. Keep the tokenizer dumb — do the sorting downstream, and fix false-positives at the registry/`ignored`-list layer, never by re-casing the source or stemming the extractor.

**How to apply:**
1. **Deterministic pre-compute (Python, not the LLM):** clean the candidate list; for each surface attach exact + fuzzy (`difflib`) registry name/alias matches. **Also flag bigram-fragments:** build `component_words = {w.lower() for entity in known_multiword_entities for w in entity.split()}` and mark any candidate whose token is a member. The tokenizer splits on whitespace, so every multi-word entity *necessarily* sheds its component words as orphan candidates — a structural guarantee, not a guess (bare `blink` surfaces from the entity `Faerzress Blink`; `blinked`/`unblinking` surface as their own separate keys because the tokenizer keys on the exact token, not the stem or case). Pre-filter this whole class in code; let the agent adjudicate only the residue. Don't make the LLM do what code can do reliably.
2. **Batch in file order** (the queue is ~reverse-alpha), ~12/batch, so spelling-variant pairs (ALL-CAPS, plural, typo) stay adjacent inside one batch and the agent can cross-link them.
3. **Canary first:** run ONE cheap sonnet agent on ~5 surfaces to confirm the 5etools MCP is reachable *inside a subagent* and the row shape is right, THEN launch the fleet. De-risks the whole run.
4. **Fleet:** one **sonnet** agent per batch (`parallel` barrier); **opus** orchestrator = the main loop (drives + assembles). Each agent ToolSearch-loads `mcp__5etools__search`/`search_monsters`/`get_*`, Reads its batch file + the flattened registry, and returns a `schema`-forced row per surface.
5. **Collision heuristic** (the core signal): one clear referent (5etools score >100, section title == surface) → likely a real entity; collides with many unrelated hits / common word / calendar term / monster-species → not an entity. `source_id: OotA` = the campaign's own module (strong campaign-relevance signal).
6. `resolution ∈ {already-in-registry, new-entity, alias-of, not-an-entity, uncertain}`; `why` leads with the KIND (unique-individual / place / faction / item / generic-type / common-word / **bigram-fragment** / artifact) so the human can filter fast. **A flagged bigram-fragment resolves to `discard` OR `alias`, decided by one question: does the fragment have an independent generic meaning?** Coined-name fragment (`Pathshutter` ⊂ `Naomi Pathshutter`) → `alias-of` the full entity (the player referred to it by that short form). Common-word fragment (`blink` ⊂ `Faerzress Blink`) → `not-an-entity`. **Ground this check in the human-curated registry + the source text (the actual quotes), NOT the ensemble's own LLM-coined subjects** — validating one LLM's tokens against another LLM's entity list re-enters the "LLM structures → LLM renders" anti-pattern (the global pipeline rule); ensemble subjects are a hint only. A flagged fragment is still a *recommendation* — a shared word can be a genuinely distinct new entity (a companion literally named "Blink"), so the human rules.
7. **Final opus pass:** assemble the CSV sorted actionable-first; run a cross-batch consistency scan (`difflib` clusters over all surfaces) to catch variant pairs that straddled a batch boundary.

Source of the candidate corpus must be the ensemble (`docs/ensemble/per_chapter/*/merged.json` + top-level `merged.json`), never raw `summaries/` — see the `_gather_triage_sources` auto-detect in CampaignGenerator `registry.py`.
