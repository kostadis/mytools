When I have multiple questions for the user (interviews, design clarifications, confirmation rounds), ask **one question at a time** and wait for the answer before posing the next.

**Why:** User explicitly requested this. Batched numbered-list questions force the user to hold multiple contexts at once, which produces shallow or skipped answers. Serial questioning keeps each decision focused and lets earlier answers shape later questions.

**How to apply:** Any time I'd naturally produce a list like "1. Foo? 2. Bar? 3. Baz?", serialize it instead — ask Q1, wait, ask Q2 based on the answer, etc. If a question has an obvious default, state it so the user can say "default" to move on. Applies to all projects, not just this one — save the same memory in global scope if this user works in other repos.
